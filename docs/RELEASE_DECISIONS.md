## Released at their repository path, byte for byte

These files are released without modification:
- the offline pipeline (`configs/`, `training/`, `analysis/close_phase4_gate2.py`);
- the serving application and container;
- the router and its protocol;
- the Kubernetes objects exported from the campaign cluster (`kubernetes/campaign/`);
- the DEV-001 NodePort service;
- the confirmatory campaign code;
- the analysis, table, figure and claims generators.

Comments in some of these files refer to internal planning documents ("blueprint", "audit Flag n", "Section K"). The files are not edited, because:
- several are pinned by hash in the freeze manifest;
- the analysis scripts must remain the scripts that produced the analysis of record.

[IDENTIFIERS.md](IDENTIFIERS.md) maps those references to the paper.

## Released by exception to the denylist

The campaign router image `rolloutsecbench-router:gate3-v2.1-execution003-layoutfix1` was built by `serving/router/execution003/Dockerfile`, which copies two files whose names match the denylist pattern `*candidate*`: `serving/router/gate3_v2_candidates/route_oracle_v2_candidate003.py` and `router_v2_candidate003.py`. Both are present in the running container, and both are byte-identical to the repository files. They are not executed: the Deployment overrides the image command and runs the mounted `router_phase7_v1.py`, which imports neither of them. They are released, along with the Dockerfile, so that the image can be rebuilt with the same contents. The three exceptions are listed as `!<path>` lines in `release/denylist.txt`.
